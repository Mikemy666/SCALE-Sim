# DATE3 Paper Experiment Guide (Exp1--Exp7)

DATE3 keeps the six DATE2 paper questions and adds an Exp7 end-to-end
approximation. The recognizable figure families are preserved,
but every reported value is regenerated by the corrected DATE3 model. Old
DATE2 numerical values are never copied into DATE3.

## Scope and comparison contract

- Exp1--Exp2 use one NPU (`P=1`) to isolate the local 30-Bank memory system:
  15 fixed SP Banks split 5:5:5 among IA/Weight/OA and 15 ACC Banks. IA,
  Weight, and OA are INT8; cross-K partial sums are INT32 Banked RMW.
- Exp3--Exp6 use the DATE3 parameterized EP workload. Exp4--Exp6 compare all
  mechanisms under the same routing, owner mapping, Detailed-NPU workload,
  analytical Peer-NPU work, dispatch, return, and combine envelope.
- The six implementable public names are `Static-555-NoPF`, `Static-Opt-NoPF`,
  `Dynamic-NoPF`, `Static-Opt-FixedPF`, `Dynamic-FixedPF`, and `PIVOT`.
  PIVOT is the paper name of the MemDomain
  architecture. `MemDomain-Safe`, `MemDomain-Raw`, and `Oracle` remain legacy
  internal diagnostics and never appear as additional paper schemes.
- Local memory stall excludes exposed Peer/communication wait and combine.
  System-cycle figures include them and report the critical path, not the sum
  of NPU times.
- Prefetch coverage and accuracy use unique Tile-lifetime bytes for every
  scheme. Proxy request-count quality is not used by paper tables.
- In multi-layer Exp5, every scheme is causally gated by that layer's Router
  visibility. A Chunk in layer L may not trigger a request for layer L+1.
- Public NoPF controls have no PIVOT Chunk coalescer and therefore use one
  architectural Weight tile per demand request (`C=1`). PIVOT may select
  `Window=0` while retaining runtime Chunk coalescing; reports call this
  distinct safety action `Coalesced-Demand`, not NoPF.
- PIVOT admits an early request only when the shared-HBM backlog, transfer,
  mapping, and Bank-ingress estimate predicts completion before first use.
  A request predicted to arrive late is converted to `Coalesced-Demand` and
  counted by `admission_rejection_count`; no useful weight bytes are removed.
- Exp5 evaluates every legal Chunk even before feedback warm-up. Candidate
  timeliness uses each coalesced HBM request's own completion time and each
  Tile's own deadline, so small Chunks retain their first-byte advantage under
  tight slack while large Chunks retain setup-amortization benefits. Exp5 uses
  relative shadow-quality feedback without an unattainable absolute floor.
- Exp4 uses four NoPF rows: Static-555, model-wide Static-Opt, Dynamic mapping,
  and an Ideal-NoPF lower-bound reference. Joint prefetch is introduced only
  in Exp5.

## Experiment map

| Experiment | Question | Main DATE3 data | Main figures |
|---|---|---|---|
| Exp1 | Do fixed SP/ACC and 5:5:5 SP ownership expose dynamic MoE memory pressure? | `outputs/DATE3/exp1/*.csv` | cycle breakdown; traffic and ideal Banks |
| Exp2 | Can one fixed IA:Weight:OA split remain best for every stage? | `outputs/DATE3/exp2/*.csv` | per-stage optimum; 91-partition heatmap |
| Exp3 | Why is fixed naive prefetch insufficient? | `outputs/DATE3/exp3/naive_prefetch_interference.csv` | performance; timeliness/occupancy |
| Exp4 | Does dynamic unified mapping outperform fixed ownership under the identical NoPF condition? | `outputs/DATE3/exp4/mapping_comparison.csv` | Static-555/Static-Opt/Dynamic/Ideal cycles; local stall; critical path |
| Exp5 | Does online Chunk/Window/Bank co-optimization improve over conventional fixed prefetch? | `outputs/DATE3/exp5/joint_prefetch.csv` plus online traces | four sensitivity heatmaps; adaptation; guard; PIVOT ablation |
| Exp6 | Is the conclusion robust for each independent model/workload/EP variable? | `outputs/DATE3/exp6/*.csv` | one four-model/six-scheme figure per variable; failure diagnosis |
| Exp7 | What is the approximate end-to-end benefit when Attention/Router and MoE/EP are composed? | `outputs/DATE3/exp7/*.csv` | complete-block speedup; path decomposition; non-MoE layer costs |

Exp6 deliberately does not require every cross-variable absolute result to be
monotonic. The within-configuration contract is what is tested. Any violation
is retained in the diagnosis figure for explanation rather than hidden.

## Commands

Generate inputs only (no simulation):

```bash
.venv/bin/python scripts/DATE3/prepare_date3_experiments.py
.venv/bin/python scripts/DATE3/validate_paper_experiments.py
```

Later, run and resume one experiment at a time:

```bash
.venv/bin/python run_date3_experiments.py --exp exp1
.venv/bin/python run_date3_experiments.py --exp exp2
.venv/bin/python run_date3_experiments.py --exp exp3
.venv/bin/python run_date3_experiments.py --exp exp4
.venv/bin/python run_date3_experiments.py --exp exp5
.venv/bin/python run_date3_experiments.py --exp exp6
.venv/bin/python run_date3_experiments.py --exp exp7
```

Exp1 and Exp2 share the same characterization pass, so either command produces
both tables. Completed hash-valid variants resume automatically. Use
`--skip-details` is valid for Exp4--Exp7 because public comparison rows now
carry byte-accurate control quality directly.

Exp6 can be split by one variable or model:

```bash
.venv/bin/python run_date3_experiments.py --exp exp6 --exp6-variable top_k
.venv/bin/python run_date3_experiments.py --exp exp6 --exp6-variable token_count --exp6-model HMoE
```

After a completed experiment, aggregation runs automatically. Figures are
generated separately:

```bash
.venv/bin/python scripts/DATE3/plot_experiments.py --exp exp4
.venv/bin/python scripts/DATE3/validate_paper_experiments.py --require-outputs --require-figures
```

## Exp7 approximation boundary

Each of the four workloads contributes one complete controlled MoE Transformer
block containing Q/K/V projections, QK transpose, QK-V multiplication, output
projection, Router, and all routed expert FF1/FF2 stages. Non-MoE GEMMs use the
same INT8 compute, INT32 ACC RMW, 30-Bank hardware, and fixed 5:5:5 SP baseline
as Exp1. The measured DATE3 MoE+EP critical path is then composed with these
non-MoE full cycles.

The formula is:

```text
ApproxBlock(policy)
  = DATE3System(policy)
  - embedded ideal non-MoE compute
  + modeled non-MoE compute and memory cycles

Speedup(policy) = ApproxBlock(Static-NoPF) / ApproxBlock(policy)
```

This is a conservative block-level approximation. Embedding, normalization,
Softmax, residual connections, sampling, cross-layer cache effects, and an
actual production model depth are not simulated, so Exp7 must not be described
as measured full-LLM inference latency.
